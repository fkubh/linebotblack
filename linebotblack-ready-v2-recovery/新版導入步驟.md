# 2026-11-01 完整部署包：reliable-inbox-v2-worker-init

這是以你提供的 ZIP 為基礎修復的完整可替換版本，保留黑名單、LINE 回覆、群組訂單、Google Sheets、簡表與收件匣補處理。此文件優先於包內舊版部署說明。

## 導入

1. 暫停原 Apps Script 補處理排程，保留既有 Google Sheets、所有資料與 Render 環境變數。
2. 解壓縮後，把 linebotblack-ready-v2 資料夾「裡面的檔案」覆蓋到 GitHub 專案根目錄，不要多套一層資料夾。包含 gunicorn.conf.py、lineborblack_cloud.py、sheets_runtime.py、reliable_orders.py、order_summary_v1.py、requirements.txt、render.yaml 及 .python-version。
3. Render 的 Build Command 設為：

   `pip install --no-cache-dir -r requirements.txt`

4. Start Command 設為：

   `gunicorn --config gunicorn.conf.py lineborblack_cloud:app`

5. 保持一個服務實例。移除 GUNICORN_CMD_ARGS 中舊有 --preload、多 worker、執行緒或其他覆蓋此設定的參數。原本 LINE、Google 憑證、試算表 ID、群組 ID、REPLAY_SECRET 等設定沿用，不要刪除。
6. Render Settings 的 Health Check Path 手動設為 `/ready`。現有服務不一定會自動套用 render.yaml。
7. 執行 Clear build cache & deploy，等待初始化完成。避免連續部署造成重複讀取。
8. 開啟 https://linebotblack.onrender.com/ready，確認 version 為 reliable-inbox-v2-worker-init 且 ready 為 true。initializing 為 true 時可查看 operation、elapsed_seconds、progress_age_seconds；若一直沒進度，提供此頁及最新 STORAGE 日誌。
9. 在測試群發送「版本」、一筆測試訂單及黑名單查詢，核對回覆和試算表，再恢復原 Apps Script 排程。既有自動補處理.gs 可沿用，不需新建第二組觸發器。

## 本次修復

- 不再於匯入應用程式時啟動背景初始化，改在 Gunicorn 工作程序啟動後執行；首次健康請求也可觸發初始化。
- 子程序建立時重設初始化狀態、鎖、配額計數與結構快取，並在請求時核對程序 ID，避免沿用父程序的 initializing 狀態。
- 每次初始化 Google API 呼叫記錄 STORAGE PROGRESS；/ready 增加程序、步驟、耗時與冷卻時間。
- 保留完整歷史掃描，不刪除資料或忽略中間空白頁。資料量大時仍可能初始化較久；本版沒有以刪除歷史來縮短等待。

## 驗證與限制

原有 34 項模擬測試與新增 4 項工作程序啟動回歸測試通過，Python 語法檢查通過。新增測試涵蓋匯入不啟動背景作業、程序 ID 改變後重設狀態與鎖、Gunicorn 啟動鉤子、診斷進度欄位。Google 與 LINE 使用模擬回應，未連線實際服務；Windows 測試未實際執行 Linux fork/Gunicorn。仍須完成上方正式環境驗收。
